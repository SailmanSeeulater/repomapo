Thread View

Hover any underlined name to see its threads. Click it to lock it and jump to its definition; if that file is not open, it opens. Up to four files stay open, and the one you used longest ago closes.

Build plan

The prototype already reads the data shape below, so most of the work is producing that shape from a real repo.

  1. Settle the feel on this page

    Play with hover, lock, pin, and the draw-everything toggle. Decide how many panes feel right and whether threads should always start at the definition or at whichever name you clicked.

    Done when you can say what you would change about the interaction.

  2. Get real edges from one repo

    Run a SCIP indexer (scip-java, which should cover Kotlin and Java) on one Spring Boot repo. Write a small script that turns the index into the JSON shape below. Check first that the indexer handles your Kotlin and Gradle versions.

    Done when ten symbols you spot-check have the same usages IntelliJ's Find Usages shows.

  3. Swap the hardcoded data for the JSON

    Add a file tree to open panes. Clicking a usage in a file that is not open opens it as a new pane, capped at four, oldest closes. Render only the visible lines so large files stay fast.

    Done when you can walk from a controller to the database call by clicking threads only.

  4. Add the rules that keep it readable

    A symbol with more than about 25 usages collapses to one thread per file with a count. Library symbols such as Spring and JDK types become a chip in the gutter with no threads. Usages outside the open panes show as stubs at the pane edge.

    Done when focusing the most-used class in the repo is still legible.

  5. Hook it into the repo graph

    Clicking a file node in the repo-level view opens that file here, so you zoom from the whole repo down to single lines.

    Done when the two views share one index and one URL scheme.

Data shape

{
  "files": [
    { "path": "store/MessageStore.kt", "lines": ["package dev.example.relay.store", "..."] }
  ],
  "symbols": [
    {
      "id": "Envelope",
      "kind": "class",
      "def":  { "file": 2, "line": 7,  "col": 11, "len": 8 },
      "refs": [
        { "file": 0, "line": 14, "col": 32, "len": 8 },
        { "file": 1, "line": 12, "col": 19, "len": 8 }
      ]
    }
  ]
}

Lines count from 1 and columns from 0. Columns come straight from the index, so overloads and same-named methods stay separate. The file also carries a name per symbol (the id is the full SCIP symbol) and a meta block with the indexer version and counts.

What will bite

  • Spring injection. A constructor parameter typed as an interface points at the interface, and the implementing class looks disconnected. You need the index's implementation relationships as a second edge type.
  • The indexer needs a building project. It hooks into the compiler, so a repo that does not build gives you no index.
  • Index size. Split the JSON per file and load a file's symbols when its pane opens.
  • Thread count. Tick the draw-everything box above. That is three small files. Focus mode has to stay the default.
